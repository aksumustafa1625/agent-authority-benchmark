# Security

## What this repository contains

A **benchmark corpus**: twenty-eight Apex source files, a JSON description of
them, and the hashes that seal both. Nothing here is deployed, executed or
installed by this repository. There is no build, no dependency, and no runtime.

## The case files are inert, and some of them are deliberately unsafe

Several cases are **examples of Apex that reads or writes past the running
user's authority** — that is what they are for. A case such as
`record-v58-without-plain` exists because a real org demonstrated that rows the
user holds no share on come back.

They are published as *measurements*, not as recommendations.

**Do not copy a case file into a production org.** Their value is that an
analyzer can be scored against them; their behaviour is the thing being
measured, not a pattern to adopt. Each carries its outcome in `corpus.json`, and
the ones that bypass an authority check say so in their rationale.

## No credentials, no org, no data

- **No credentials of any kind** — no keys, tokens, session ids or auth URLs, in
  the working tree or in the history.
- **No org identifiers** — the fixture is described in `corpus.json` by shape
  (one object, one user, stated permissions), never by org id or instance.
- **No customer data.** The fixture is synthetic and exists only to make the
  measurement reproducible.

## Integrity is the security property that matters here

For a benchmark, the risk is not a leak — it is a **silent substitution**. A
corpus that can be edited after publication, or a case tuned after a tool was
scored against it, is worthless regardless of how carefully it was measured.

Two things address that:

- Every file is sealed by sha256 in [`CHECKSUMS.md`](CHECKSUMS.md), generated by
  the exporter and never typed
  ([ADR-004](docs/adr/ADR-004-the-seal-is-generated-never-typed.md)).
- **CI verifies the seal on every push**, running the same command the README
  gives a reader. A documented procedure nobody runs is the same failure as a
  hand-typed hash.

If you hold an earlier copy and its `CHECKSUMS.md` does not match this one, that
is expected and intended — see the Errata in the README. Every changed value is
listed there, in the same words as in `corpus.json`.

## Reporting a problem

The most useful report is **a published value that is wrong** — v1.1 exists
because one derived field was wrong for five of twenty-one cases. Open an issue,
or contact the author via https://mustafaaksu.dev.

There is no bug bounty. A correction to a measurement is worth more here than a
vulnerability report, because the corpus has no attack surface and every claim in
it is meant to be falsifiable.
