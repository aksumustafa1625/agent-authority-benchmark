# Architecture Decision Records

This repository publishes measurements, so its decisions are **methodological**
rather than architectural: where ground truth comes from, what is published when
it is weak, and what happens when a published value turns out to be wrong.

Each record states the constraint, the decision, what else was on the table, and
what the choice costs.

## Index

| # | Decision | The constraint behind it |
|---|---|---|
| [001](ADR-001-the-oracle-is-a-live-org.md) | The oracle is a live org, never my model of the rules | Labels derived from my own analyzer are a mirror, not an oracle |
| [002](ADR-002-provenance-is-published-per-case.md) | Every case publishes where its ground truth came from | Uniform confidence hides what a sceptical reader needs |
| [003](ADR-003-seven-cases-carry-no-verdict.md) | Seven cases carry no verdict, and stay in | An org cannot measure the absence of an analyzer's knowledge |
| [004](ADR-004-the-seal-is-generated-never-typed.md) | The seal is generated by the exporter, never typed | A hash the README repeated went stale on the first regeneration |
| [005](ADR-005-errata-over-silent-correction.md) | A wrong value gets an errata entry and a version bump | A benchmark that changes silently is not a benchmark |

## The two worth reading first

**[ADR-001](ADR-001-the-oracle-is-a-live-org.md)** is why this corpus exists at
all. If the expected outcomes come from the same model as the analyzer being
scored, the benchmark measures consistency and calls it correctness.

**[ADR-005](ADR-005-errata-over-silent-correction.md)** is the one that cost
something. v1.0 published a derived field that was wrong for five of twenty-one
adjudicated cases, including a negative control mislabelled as an escape. The
record explains why that is published in a table at the top of the README rather
than quietly repaired.

## Format

Status · Date · Author · Context · Decision · Alternatives Considered ·
Consequences · References.

The same structure is used across the sibling repositories.
